## Co trzeba zrobić, aby nie stracić dzisiejszych zmian

### Na swoim komputerze

1. Otwórz PowerShell w **folderze lokalnego repozytorium**, z którego uruchamiasz Rojo.
2. Wykonaj:
   ```powershell
   git status
   git branch --show-current
   git pull
   ```
   Oczekiwana gałąź: `feature/saab-ground-placement`. Jeśli masz lokalne niezapisane zmiany, najpierw je zachowaj — nie wymuszaj resetu.
3. Zostaw uruchomione `rojo serve` zgodnie z obecną konfiguracją i sprawdź, czy w Roblox Studio wtyczka Rojo jest połączona.
4. Uruchom **Play** i wyszukaj w Output komunikaty:
   - `[CityAssets71] IMPORT OK`
   - `[CityPrefab79] DONE: 20 buildings`
   - `[CityInfill85] DONE: 8 extra prefabs`
   - `[CityStreetscape79]`
   - `[CityInfra87] DONE: 2 parking lots, 1 fuel stations`
   - `[CityAccess89] DONE: 3 markers, 3 refined driveway links`
5. Zatrzymaj Play. Zapisz bieżący **plik miejsca** Roblox Studio (`File → Save to File` lub właściwą metodą publikacji wersji roboczej), jeśli wprowadzałeś ręczne zmiany w Studio. Zachowaj też kopię `.rbxl`/`.rbxlx` w bezpiecznym miejscu.
6. Jeśli lokalnie zmieniłeś *pliki należące do repozytorium*, wypchnij je oddzielnym commitem po przejrzeniu `git diff` i `git status`. **Nie używaj bezmyślnie `git add .`**, ponieważ kopie gry mogą być duże i niezamierzone.

### Ważna pułapka: Studio Play to nie trwały zapis mapy

Dzisiejsze generatory mają kontrolę `RunService:IsStudio()` i tworzą obiekty **podczas Play**. Po zatrzymaniu testu powstałe modele mogą zniknąć z widoku edycji. **Wysłanie skryptów na GitHub nie oznacza automatycznego zapisania zbudowanych prefabrykatów do pliku gry ani działania ich w opublikowanej grze.** To obecnie powtarzalny podgląd deweloperski.

Przed publicznym wydaniem należy:
- zdecydować, czy zapisać (wypiec) układ 28 budynków oraz dekoracje do trwałego miejsca Roblox, czy uruchamiać poprawiony generator na serwerze produkcyjnym;
- zweryfikować licencje/uprawnienia i dostępność assetu Creator Store w opublikowanym doświadczeniu (aktualnie potwierdzono tylko Studio);
- usunąć lub wyłączyć stare ręczne kopie skryptów w Studio po sprawdzeniu mapowania Rojo; logi wielokrotnie wykazywały duplikaty startu;
- wykonać testy wydajności, kolizji, multiplayer oraz zapisu danych; nie nadpisywać danych ekonomii przypadkowymi testami.
